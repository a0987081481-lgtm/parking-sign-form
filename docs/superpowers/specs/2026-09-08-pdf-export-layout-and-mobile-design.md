# PDF 匯出版面與手機預覽修正設計

## 目標

修正公開簽認單匯出 PDF 的兩個問題：

1. 設備卡片在分頁時被硬切，造成內容或邊框貼近頁面邊界、看起來被吃掉。
2. 手機上偶爾把 PDF 原始資料流當成文字顯示，而不是交給 PDF 閱讀器預覽。

## 不變更範圍

- 不修改 `projectName`、`siteCode` 或其他既有欄位 key。
- 不修改公版設定資料格式、localStorage key、Worker API 或 GitHub 同步流程。
- 不修改獨立簽名模式與簽名資料結構。
- 不新增後端服務或改變 GitHub Pages 部署方式。

## 版面方案

維持目前 `html2canvas` 與 `jsPDF` 架構，但改變頁面放置規則：

- 以設備卡片為主要分頁單位。
- 若完整設備卡片可放入目前頁面剩餘空間，保持完整放置。
- 若完整設備卡片放不下但可放入空白新頁，先換頁再放置，避免從卡片開頭切斷。
- 若設備卡片本身高於單頁，保留設備標題、名稱與編號；只在檢查項目之間切片。
- 每個切片上下保留固定安全間距，避免內容或邊框貼住 PDF 頁面邊緣。
- 其他區塊沿用目前流程，避免擴大修改範圍。

## PDF 輸出方案

- 由 jsPDF 產生 Blob，明確使用 `application/pdf` MIME 類型。
- 以暫時的 `<a download>` 連結觸發下載，檔名沿用現有命名規則。
- 在輸出前檢查 Blob 的 MIME 類型與前五個 ASCII 位元組是否為 `%PDF-`。
- 若輸出失敗，顯示繁體中文錯誤訊息，不產生看似成功但無法閱讀的檔案。
- 不保證所有手機檔案管理器一定直接進入預覽器；驗收重點是下載檔案本身為合法 PDF，且不再因前端輸出格式不明而被當成純文字。

## 測試設計

新增或調整 Node 內建測試，至少涵蓋：

- 設備卡片在剩餘空間不足時會移到新頁，而非直接從卡片中間開始。
- 超過單頁高度的設備卡片只在檢查項目邊界切分。
- PDF Blob 輸出使用 `application/pdf`。
- PDF 輸出驗證 `%PDF-` 標頭。
- JPEG 壓縮、既有 PDF capture scale 與現有格式測試維持通過。

## 驗收條件

- 產出的 PDF 不再把一般設備卡片切在標題、欄位或檢查項目中間。
- 多頁 PDF 每頁內容與邊框保留安全間距。
- 產出檔案可由 PDF 閱讀器正常解析，檔案 Blob MIME 為 `application/pdf`，標頭為 `%PDF-`。
- `node --test tests/*.test.js` 全部通過。
- 公開頁、欄位、簽名、維護頁與同步功能沒有行為回歸。
